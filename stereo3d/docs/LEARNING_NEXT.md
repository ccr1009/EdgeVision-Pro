# LEARNING_NEXT — 这个项目你能自己补什么（学习向）

> 项目骨架已跑通，但下面这些是**留给你自己动手**的空位。每条都标了难度和「做完能讲什么」。
> 原则照旧：AI 当陪 debug，代码你自己敲。

## A. 必做（把「未标定」变成「已标定」）

### A1. 打印棋盘格 + 抓 30 对图（半天）
- A4 纸打印 9×6 内角点棋盘格（`tools/calib/README.md` 有现成说明），贴硬纸板。
- 跑 `tools/calib/capture_pairs.py`，提示：**15 个以上角点清晰的图才算好图**，斜着放、远近都拍。
- 自检：每张图角点数打印 ≥54（9×6=54）。
- 能讲：为什么标定图要「倾斜+远近」覆盖——标定要激发旋转矩阵的全部自由度。

### A2. 跑标定 + 看懂两个 RMS（半天）
- `stereo_calibrate.py` 输出：单目 RMS、双目 RMS、基线长度。
- 自查线：双目 RMS ≤ 1.0 px 才能用；基线应该 ≈ 两颗摄像头物理间距（卡尺量一下对照）。
- 能讲：RMS 是什么（重投影误差）、为什么双目 RMS 一般比单目略大（多了一组外参约束）。

### A3. 极线验收（半天，最出彩）
- `verify_calib.py` 画水平极线对照图：**矫正后同名点 y 差中位数应 ≈ 0 px**。
- 这是你面试演示的「量化证据」：未标定时 y 差是多少（跑一次 --no-calib 的 SGBM 有效率作对照），
  标定后降到多少，SGBM 有效视差占比提升多少。三个数字一个故事。

## B. 性能（task-5 进行中，你可以自己验一遍）

### B1. SGBM 并行验证（2 小时）
- 板上打印 `cv::getNumThreads()`，`perf top` 看 SGBM 期间是不是只吃一个核。
- 自己做 A/B：`cv::setNumThreads(1/2/4/6)` 各跑 200 帧记 sgbm_ms。
- 能讲：OpenCV 并行框架按行切块 SGBM，为什么加速比到不了线性（内存带宽是 RK3588 共享瓶颈）。

### B2. num_disp 消融（2 小时）
- 64/48/32 各测：耗时 vs 有效视差占比 vs 人脸距离读数。
- 先算再测：B=60mm、fx=554@640，0.5m 人脸视差 = 554×0.06/0.5 ≈ 66px？
  还是 6.6px？**自己推一遍再看数**（注意 proc 尺度 fx 是 554 不是 1108）。
- 能讲：num_disp 上限决定最大可测深度（近处大视差会被裁掉，这就是「太近测不了」的原理）。
