# 第 15 章 压力面与反问

> 一句话心智模型：压力面考的不是你知道多少，而是**你在不知道的时候会怎么表现**。面试官故意冷脸、故意说"这很简单吧"、故意质疑数字真假，都是在看你会不会崩、会不会编。这一章只教三件事：被问倒怎么退、被质疑怎么接、轮到你问的时候怎么显得专业。

## 一、先建立心智模型

压力面的本质是一场**信任测试**，不是知识测试。技术面考"你会不会"，压力面考"你说的我敢不敢信"。所以最危险的动作不是答错，而是**为了不答错而编**——编一次，前面四十分钟的可信度全部作废。

```
                     压力面的六种下刀方式，你各有一招

   ① 连环追问   "那为什么不是 3 倍？"        ---> 三步法：确认 / 最近答案 / 划边界
   ② 质疑归属   "这是你自己做的吗？"          ---> 讲决策链，不讲结果清单
   ③ 贬低难度   "不就是跑个 demo 吗？"        ---> 承认简单部分，指出不简单的分歧点
   ④ 质疑数据   "这个数据真的假的？"          ---> 报口径 + 报样本量 + 报失效条件
   ⑤ 冷脸沉默   不点头、不接话、看天花板      ---> 自己收尾，把话语权交回去
   ⑥ 压力反问   "你比别人强在哪？"            ---> 不比人，比"我做过你没做过的事"

   一条总原则：可以不知道，不可以装作知道。
```

**记住这一个比喻**：面试像**在冰面上走**，每个回答都是往冰上踩一脚。踩实了继续走，踩虚了立刻退回岸边换条路。**"我不知道"不是掉进冰窟窿，是站在原地不动**——站着永远安全，硬往前踩才是真的掉下去。

## 二、问答正文

### Q：被问倒了怎么办？三步法具体怎么说？

**一句话答案：** 第一步**先确认问题**（复述一遍，确认对方问的是哪一层），第二步**给最接近的答案**（我做到哪一步、相邻的什么我做过），第三步**明确划边界**（"再往下我没验证过，不敢瞎说"）。

**展开讲：** 三步里最值钱的是第一步，因为**一半的"被问倒"，其实是没听清对方问的是哪一层**。他问"你的三核怎么并行"，你以为他问有没有用多线程，于是答了一堆 pthread 绑核，其实他想问 NPU 的核怎么被分派。先复述一句"您是想问我的线程怎么排，还是问三个 NPU 核怎么绑定？"——两种情况立刻对上，而且这句复述本身就证明你懂这里有区别。

第二步的关键是"**给最近的东西，不给最远的东西**"。被问到 MPP 和 RGA 之间怎么传 fd，我没写过，但我说"零拷贝这条路我评估过，架构里留了后端抽象和缓冲生命周期管理，还做过对照实验证明输入侧不是瓶颈、只差 0.4%，所以优先级放在砍 CPU 回退上"。我不懂 fd 传递细节，但我懂它在我系统里的位置和取舍。

第三步要说完整句子："再深我就不确定了，我知道的是输入侧不是瓶颈这个结论，fd 怎么在 MPP 和 RGA 之间传，我没写过。"

**如果被追问「你这么说，不就是承认自己不行吗？」：** 恰恰相反。面试官每天听到大量半真半假的答案，一个能清楚画出"我知道到这里、再往前是空白"的人，前面每一句的可信度都被抬高了。真正掉分的是越问越虚、自己绕不回来的人。

> 【费曼讲解】为什么"我不知道"比编一个答案更安全？
> 生活类比：你在给人指路，路口三条岔路你只认识一条。老实说"另外两条我没走过"的人会被记住为靠谱；随手一指的人，等人走错回来，就再也不会被信。
> 不懂的人会怎么错想：以为面试是考试，空着就是零分，所以拼命填点什么上去，哪怕自己都知道是猜的。
> 一句话戳破：面试不是打分表，是**采样**——他采的是"这个人以后说的话，我要不要信"。
> 回到术语：所以正确动作是给出置信区间，把"我知道的""我猜的""我不知道的"三档明确分开，这在工程上叫不确定性表达。

### Q：完全不会的时候，三句话术是什么？

**一句话答案：** 第一句"这块我没直接做过"；第二句"但我做过跟它相邻的 X，我的理解是……"；第三句"再深我就不确定了，要回去查证"。三句加起来十几秒，比硬编三分钟强十倍。

**展开讲：** 这三句分别完成三件事：**降预期、给价值、划责任**。被问"你做过 GDB 调试吗"，诚实答案是："用过但不熟练，主要抓过一次 segfault、定位到具体某一行。Valgrind 我没在这块板上跑过——板子是 aarch64，我还没交叉编过去。所以内存泄漏我只能从代码层面把握（RAII、队列有界），没有工具层面的证据。"说完对方不会打低分，反而知道你知道工具链的边界在哪。

**如果被追问「那你为什么不花时间学一下？」：** 说优先级："当时我判断瓶颈在 NPU 回退上，那块直接决定帧率，所以时间先花在那。这也是一种取舍。"这把"不会"翻译成了"我做过优先级判断"。

### Q：面试官质疑"这是不是你自己做的"，怎么答？

**一句话答案：** 不要重复讲"我做了什么"，改成**讲决策链**——为什么这么选、排除了什么、哪一步卡了多久、犯了什么错、怎么发现的。一个人可以背下别人的结果，但背不出自己踩过的坑。

**展开讲：** 这句话的潜台词是"你说得太顺了，顺得像背的"，所以最忌讳继续流畅背书。正确做法是**主动交出不完美**，讲三件只有亲手做过才知道的事。

第一件，我一开始判断错的地方：以为三核掩码设成三核就有三倍，结果只有 3.3%；以为余弦相似度 0.99651 就代表量化无损，结果分类分支塌缩成常数 0.5。

第二件，卡住的现象：MPP 那个 -1012 错误码，怎么调参数都是同一个码，卡了很久，最后查出来是系统预装的库和驱动 ABI 倒挂，自己编静态库才通。

第三件，我放弃了什么：MPP 硬编 JPEG 我实现完、验证完、`/proc/interrupts` 也证明真走了硬件，结论是比软编慢，于是划掉。**做完再划掉**和"没做"是两回事，这件事最能让对方相信你确实在一线。

**如果被追问「那你说说这个数是怎么来的？」：** 立刻报采集方式。15.95 ms 是 `rknn_inputs_set` 加 `rknn_run` 加 `rknn_outputs_get` 的整周期，跑 200 次取中位数，输入是合成 640×640 灰图，不含解码、RGA 缩放、NMS 和绘制。能报到这一层，基本没人再怀疑。

### Q：被说"这个很简单吧，不就是跑个 demo 吗"，怎么接？

**一句话答案：** 先**大方承认简单的部分**，再把话题挪到**分歧点**上：简单的是"跑起来"，难的是"知道它为什么慢、慢在哪、哪段能砍、砍了掉多少精度"。

**展开讲：** 这话最容易被激怒，急着反驳"不简单啊"就掉进"证明自己不简单"的陷阱，接下来每句话都像自辩。我一般三步走：先顺水推舟，"确实，让它跑起来不难，官方 demo 我第一天就跑通了"；再给分歧点，"但跑通之后我拿到 37 毫秒，官方宣称 5.5 到 7，差了六七倍，这才是花时间的地方"；最后给证据，"我拆成 125 个算子，发现 49% 的时间根本不在 NPU 上"。三步之后"简单"这个说法自己就站不住了——不是因为我反驳，是因为我给出了一个他不知道的分歧点。

**如果被追问「那你觉得这个项目有什么技术含量？」：** 两条。一是**归因能力**：同样拿到 37 毫秒，大部分人会说"RK3588 就这水平"，我能指出 `dfl/Transpose` 一个算子吃掉 9181 微秒，而同一个算子在另一个位置只花 1475 微秒，所以是放置问题不是算力问题。二是**验收能力**：我没停在"余弦 0.99651 看起来很好"，而是去跑了真 mAP，才发现分类分支已经废了。

### Q：被质疑"这个数据真的假的"，怎么答？

**一句话答案：** 三件一起报：**口径**（测的是哪一段）、**样本量**（跑多少次、多少张图）、**失效条件**（什么情况下不成立）。三条都有，数字就是真的；缺一条，对方都有理由怀疑。

**展开讲：** 大多数人被质疑数据时第一反应是重复数字、加重语气，这是最没用的。可信度不靠语气，靠能否说清边界。标准答法三段：第一段报口径，"20.58 毫秒是 bench 口径，含推理、IO 搬运和后处理，不含解码和 CSC；算上全链路是 55.84 毫秒"；第二段报样本量，"跑 200 次取中位数，同时给 p95 和 p99，因为只看均值会被调度抖动骗"；第三段报失效条件，"换板子就不成立，主频、带宽、散热都会影响；但'DFL 头会回退到 CPU'这个结论是结构性的，换板子照样成立"。

还有一条特别好用：**主动说出自己那个数不好看的地方**。提 2.21 倍时同时说"并行效率只有 73.5%，每核负载只有 49%"。一个主动报短板的人，对方会默认他报的长板也是真的。

**如果被追问「你这些数有没有可能测错了？」：** 有可能，所以我做了对照组。编译优化那次特意留了两组"不该变"的量：MPP 硬解 1.250 到 1.322（+5.8%）、letterbox 1.184 到 1.222（+3.2%），都在噪声范围内；而 CSC 从 52.016 掉到 33.583，1.549 倍。如果所有数字一起变好，大概率是环境变了；只有该变的变了，才说明是真的。

> 【费曼讲解】为什么"对照组"比数字本身更能证明你没测错？
> 生活类比：想证明一副眼镜让人看得更清楚，光说"戴上后我认出 10 个字"没用——得说"没戴的时候我也试了，只认出 6 个；而且戴不戴，我走路速度都一样"。
> 不懂的人会怎么错想：以为优化前后各跑一次、数字降了就是生效，不知道如果机器正好降温了、或者没别的进程在跑，任何改动都会"生效"。
> 一句话戳破：**只测"该变的"，你分不清是改动起作用还是环境变了；必须同时测"不该变的"，它才是你的温度计。**
> 回到术语：这就是 A/B 对照里的控制变量——把预期收益为零的那几段当基线漂移的度量，用它们的波动去判断目标段的差异是否超出噪声。

### Q：面试官全程冷脸、不点头、还打断你，怎么办？

**一句话答案：** 冷脸大概率**跟你无关**——那是他当天的第 N 场，或者他在刻意制造压力。你要做三件事：**自己收尾**、**把话语权交回去**、**守住节奏**。

**展开讲：** 真对你没兴趣的面试官会提前结束，而不是冷着脸听四十分钟。冷脸是**测试手段**，专看你会不会因为缺正反馈就开始乱、开始堆词、开始自我否定。动作三条：**自己收尾**，正常对话靠对方点头判断"这段可以了"，冷脸时这信号消失，很多人就会一直讲、越讲越散，所以我给每个回答定九十秒上限，说完主动停，加一句"这一段大概是这样，您想往深里问哪块"；**交回话语权**，被打断不要抢，顺着他的问题走，被连续打断三次以上说明信息密度不够，该缩句、直接给结论；**守住语速**，紧张的第一表现是语速变快、句子变长，我会刻意在关键数字上放慢，在压力下还能把数字说清楚本身就是稳定性的证明。

**如果被追问「你怎么知道他是故意的还是真不满意？」：** 分不清也不需要分清，两种情况的应对一样：收短、给结论、交回话语权。真不满意的话，下个问题会问得更基础，那时再补。

### Q：反问环节问什么？问错了会怎样？

**一句话答案：** 问错了会显得你只关心自己，或者显得没做功课。安全问法是**问对方工作里具体的困难**——这类问题同时证明你懂这行、关心真实问题、想长期待。挑三到四个问，别一口气问完。

**展开讲：** 反问是面试里唯一你掌握主动权的十分钟，大部分人却浪费了：要么说"没有了"，要么问"公司文化怎么样"这种谁都能答、答了没信息量的话。我的筛选标准是三条：这个问题是不是**只有这个团队的人答得出来**；答案会不会**影响我的判断**；问出来会不会显得我在意成长而不是待遇。

| 技术类问法 | 为什么这样问显得专业 |
|---|---|
| 团队现在部署的模型一般多大、跑在什么芯片上 | 说明你关心真实工作负载，不是抽象技术 |
| 端侧的瓶颈更多在精度还是内存带宽 | 用一个二选一暴露你懂端侧瓶颈的分类 |
| 有没有固定的性能基线和回归流程 | 呼应你自己做 bench 和 12 条回归的经历 |
| 模型从训练到上板这条链路，哪一段最耗时 | 说明你知道部署不只是推理，还有转换量化验收 |
| 有没有哪块想优化但一直没排上期的 | 问出真实痛点，也是你入职后第一件能做的事 |

| 团队类问法 | 为什么这样问显得专业 |
|---|---|
| 这个方向几个人、怎么分工 | 关心协作方式，不是关心福利 |
| 新人进来一般先接什么类型的任务 | 你在想"我多久能上手"，不是"我能拿到什么" |
| 代码评审和文档是强制还是自发 | 在意工程规范的团队会喜欢这个问题 |
| 跨部门协作多吗，比如和算法、硬件团队 | 端侧部署天然是三不管地带，问到了点上 |
| 团队最近一次线上事故是什么原因 | 敢问事故，说明你关心可靠性而不只是功能 |

| 成长类问法 | 为什么这样问显得专业 |
|---|---|
| 进来第一个月，做到什么算合格 | 把期望前置，是职场成熟度的直接体现 |
| 有没有固定的技术分享或读论文机制 | 关心长期输入，不是只想找份工作 |
| 这个岗位一年后，做得好的人什么样 | 关心路径而不是关心头衔 |
| 我没做过量产交付，团队会给这种机会吗 | 主动暴露短板并问成长路径，比假装全能强 |
| 您当初为什么选择来这家公司 | 把面试官从考官变成被访者，气氛立刻松下来 |

**如果被追问「你问这些是不是在挑公司？」：** 坦白说是在互相挑，但补一句"我更在意能不能在这里把端侧这条路走深，因为校招第一份工作决定的是方向不是薪水"。这同时解释了为什么我问的都是技术和工作方式。

### Q：HR 面那八个常问问题怎么答？

**一句话答案：** HR 面不考技术，考的是**稳定性、动机真实性、边界感**。答案要短、要具体、要不留把柄——每个问题控制在四句话内，别展开成一篇文章。

**展开讲：** 八道题逐个给答法框架。

| 问题 | 怎么答 | 为什么这样答 |
|---|---|---|
| 为什么选端侧 AI 这个方向 | 讲一个具体触点：跑到 37 毫秒卡住、拆出 49% 在 CPU 那一刻觉得有意思，之后一直在做这件事 | 有触发点比"我觉得前景好"可信十倍，前景好是判断，触点是事实 |
| 职业规划 | 三年内把从模型到板端交付这条路走完整，先补量产交付经验 | 说的是能力项不是头衔，HR 最怕"三年当总监"这类空话 |
| 优点和缺点 | 优点给有证据的（用测量代替猜测）；缺点给真短板（没做过量产、没跑过 Valgrind） | 缺点不敢说等于自夸，说了真短板反而显得自省 |
| 为什么选这家公司 | 说清你在意它的哪条业务和技术栈，能对上你的项目 | 泛泛夸公司等于没做功课 |
| 手里有几个 offer | 有几家就说几家，不吹数量，加一句"还在看方向匹配度" | 编数字被追问就露，且显得浮躁 |
| 能接受加班吗 | 能接受节点上的冲刺，也希望是阶段性而非常态 | 直接说"能"是敷衍，说"不能"是拒绝，说清边界才专业 |
| 期望薪资 | 给一个区间，依据是本地校招同岗位水平，强调更看方向 | 咬死一个数容易谈崩，给区间显得成熟 |
| 你还有什么想问的 | 问培养路径、问新人考核标准、问团队节奏 | 把最后一句留给成长，HR 面就收得住 |

**如果被追问「你这么说是不是太保守了？」：** 可以说"我倾向于先把边界说清楚，因为我做技术项目也是这个习惯——先测出真实范围再谈优化"。这么一句就把"保守"翻译成了"可靠"，也顺手回了技术面的人设。

## 三、这一章的"记忆锚点"

- **三步法九个字**：先确认、给最近、划边界。第一步最值钱，一半的"被问倒"是没听清。
- **三句话术**：我没直接做过 / 但相邻的 X 我做过 / 再深我不确定。
- **质疑归属的解法**：讲决策链不讲结果清单，主动交出不完美、卡壳点、做完又划掉的东西。
- **质疑简单的解法**：承认跑通很简单，把话题挪到"为什么慢、慢在哪、砍了掉多少"。
- **质疑数据的解法**：口径、样本量、失效条件，三样一起报，外加主动报短板。
- **反问的三条筛选**：只有这个团队能答、答案会影响我的判断、显得我在意成长。
- **HR 面一条底线**：短、具体、不说满。

## 四、面试官可能从哪下刀（预演）

| 他可能问 | 你怎么接 |
|---|---|
| 这个项目是你独立做的吗 | 讲决策链：先错在哪、卡了多久、什么做完又划掉了；再补一个只有亲手做过才知道的细节 |
| 不就是跑个官方 demo 吗 | 承认跑通简单，立刻给分歧点：官方 5.5 到 7 我实测 37，拆到 125 个算子找到病灶 |
| 你这数字我怀疑 | 口径、样本量、失效条件一起报，再补对照组（该变的大变、不该变的不变） |
| 你在团队里算强还是弱 | 不比人，比事：我做过从模型导出改到系统服务化的完整链路，也知道自己哪块没做 |
| 你这块没做过，为什么还投 | 说清可迁移的部分：测量方法论、逐层归因、真指标验收，换平台照样用 |
| 如果我给你一个你不会的任务呢 | 给三步：先确认需求边界、找最近的可迁移经验、明确哪一步需要人帮 |
| 你还有什么问题问我 | 从技术、团队、成长三类挑三到四个，只问这个团队能答的 |
| 你今天表现得不太行 | 不辩解，问一句"您觉得最该补的是哪一块"，把评价变成反馈 |
