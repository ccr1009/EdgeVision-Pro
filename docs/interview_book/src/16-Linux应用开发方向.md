下面按简历 A 的小节顺序给成品话术。这些不是提纲，是能直接说出口的整段话，照着念两遍改成自己的语气。

**30 秒口述版 · 开场定位。** 我做 Linux 应用层开发，主线是 C++17 加 POSIX 系统编程，落在一个 RK3588 边缘视觉推流网关上：单进程贯通采集、硬解、推理、推流，我自己定了 248 字节定长帧协议，用有界队列和背压把稳态做到零丢帧。另一条线是多外设守护服务，V4L2 双摄、ALSA 双麦、systemd 托管、状态机巡检。我在意可测量、可复现。

**30 秒口述版 · 现代 C++ 与并发。** 并发骨架是 pthread 的 mutex 加条件变量、生产者消费者、两条有界队列，队列满了丢最旧，退出靠 `volatile sig_atomic_t` 标志加 `broadcast` 唤醒再逐个 `join`。条件变量一律用 `while` 包住判断，因为 `pthread_cond_wait` 会虚假唤醒。`std::atomic` 只在看板运行标志和压测完成计数上用过两处。Cache 局部性是真拿数据换的：后处理把类别循环挪到外层走连续地址，解码从 3.19 ms 降到 1.79 ms。

**30 秒口述版 · Linux 系统与网络编程。** Socket 最核心的一句话是 TCP 是字节流不是消息流，所以要么带长度前缀，要么定长。我选定长，248 字节，`#pragma pack(1)`，没有长度解析、没有动态内存分配，天然抗粘包和半包。非阻塞和 epoll 我单独写过单线程反应堆的 lab，`fcntl` 拿 `F_GETFL` 再或上 `O_NONBLOCK`，ET 模式必须读到 `EAGAIN` 才收手。信号方面 `sigaction` 收 SIGINT/SIGTERM 做有序退出，全链路屏蔽 `SIGPIPE`，因为客户端一断，`write` 默认就给你的进程发致命信号。

**30 秒口述版 · 外设与工程体系。** 外设这条线踩得最实的是 V4L2 帧率：代码里只设了 FOURCC 和分辨率、没设帧率，驱动默认协商到 20 fps，表现出来就是每帧 50 ms。查法分三层：先证明硬件支持 30，再看运行时协商成什么，最后回源码搜谁设了帧率。MPP 是硬解 MJPEG，p50 1.03 ms，比 OpenCV 软解 7.76 ms 快一个量级，中途踩了预装动态库和 5.10 内核驱动接口不兼容，`put_packet` 恒返回 `-1012`，最后自己源码编静态库。构建这块，我发现跑了一个多月的工程 `CMAKE_BUILD_TYPE` 是空的，一个 `-O` 都没开。

**30 秒口述版 · 服务化治理与高可用。** daemon 化和 systemd 是两条路，别一起用：`daemon(0,0)` 自己 fork、`setsid`、重定向 0/1/2，父进程退出，这时 systemd 还写 `Type=simple` 就会跟错 PID。所以我讲的时候分开：要么前台交给 systemd，要么自己 daemon 化、用 forking 加 PIDFile。自愈靠 `Restart=always` 加 `RestartSec`，崩了 5 秒拉回来。退出路径统一用 `sigaction` 收 SIGTERM，handler 里只置标志，清理放主循环做。

**30 秒口述版 · 项目一：全链路与背压推流。** 整条链路在一个进程里：V4L2 采 MJPEG，MPP 硬解，CPU 侧做 CSC 和 letterbox，三个独立 context 绑三颗 NPU，DFL-Free 后处理，最后 TCP 推 248 字节结构体。线程是 1 采集、3 推理、1 推流，中间两条有界队列，容量压得很小，满了丢最旧——实时视觉里积压等于延迟。建联那一刻会清空存量，不然新客户端一上来先看三秒历史画面。上位机那边稳定 19.2 FPS。

**30 秒口述版 · 项目一：剖析、图重构与构建优化。** 我第一版也以为 NPU 慢，官方量级是几毫秒，我测出 37.19 ms。但我没先改代码，先逐层剖析：125 个算子里 115 个在 NPU 上合计 19.23 ms，另外 10 个回退到 CPU 合计 18.44 ms，占 49%。那 10 个是 DFL 头的 Transpose/Softmax/Reshape，我把整个头切掉、用自研 C++ 解码接盘，纯推理到 15.95 ms，全链路 20.58 ms。构建是 Release 加 `taskset` 绑 A76 做 A/B，CSC 从 52.016 降到 33.584 ms，全链路 76.928 到 55.836 ms，二进制 206,256 字节降到 75,688。

**30 秒口述版 · 项目二：外设与服务化。** 项目二的外设是双路 1280×720 的 UVC 摄像头加两路 USB 麦克风。摄像头那个坑就是帧率没显式请求，修完 400 帧长测均值 33.33 ms、p95 33.50 和 33.39、最大偏差 0.76 ms。麦克风走 ALSA 的 `hw:5,0` 和 `hw:6,0`，16 kHz、S16_LE、双声道，能秒录——这里我会主动说边界：做到设备枚举和参数配置这一层，没做到把 PCM 接进识别。服务化是 `daemon(0,0)` 那套，加 SIGTERM 有序释放。

**30 秒口述版 · 项目二：观测解耦与状态机。** 观测就是读 procfs 和 sysfs：`/sys/class/thermal/thermal_zone` 下逐个读 type 和 temp，一共 7 个温区；`/sys/kernel/debug/rknpu/load` 解析三核负载；`/proc/meminfo` 拿 MemTotal 和 MemAvailable。架构上把数据面和控制面拆成两个端口：9000 只推定长检测帧，8088 是控制面，查健康度、控 LED、取一帧采样。状态机是 5 秒一个周期的三态机，NORMAL、PERSON_ALERT、THERMAL_ALERT，进出用不同阈值和不同连续次数做迟滞，采样失败就冻结计数不翻转。

### Q：简历写"ALSA 通过 hw:5,0 与 hw:6,0 实现双路 USB 麦克风 16 kHz PCM 采集"，这条到底怎么答？

**一句话答案：** 拆三件事答——设备怎么定位（`hw:5,0` 是 card 5 的 device 0）、参数怎么定（16 kHz、S16_LE、双声道、period 与 buffer）、你做到哪一层（设备枚举加参数验证做到了，接进识别没做）。

**展开讲：** 编号这一层 Q2 单独讲，这里只记着 5 和 6 是内核枚举出来的号。参数层是 `-f S16_LE -r 16000 -c 2`，S16_LE 指小端 16 位有符号。延迟层看两个旋钮：`period size` 决定一次中断搬多少数据，`buffer size` 决定能容忍多长抖动。

最后一层是边界：我做到设备枚举、参数配置、秒级录制验证，**没做到**把 PCM 接进 ASR。这句必须自己说——简历上"低延迟同步采集"后面，考官一定会问"同步怎么做的""丢帧怎么处理"，你得立刻分清哪一问在射程内。

**如果被追问「两路怎么做到同步？」：** 两路各自 `snd_pcm_open`、两个线程各自 `snd_pcm_readi`，靠采样计数对齐，不是硬件同步时钟。真要做波束成形或声源定位，必须同一个 device 的多通道或硬件同步触发，那我没做。

**如果被追问「xrun 是什么？」：** ALSA 的 overrun，应用取数不及时、环形缓冲被写爆，`snd_pcm_readi` 返回 `-EPIPE`。处理是 `snd_pcm_prepare` 重新准备再继续，同时记次数——次数一多就说明读取周期跟不上。

> 【费曼讲解】`hw:5,0` 里的 5 和 0 到底是什么
>
> ① 生活类比：去医院挂号。card 是"哪个诊室"，device 是"这个诊室里的第几台设备"。你上次被分到 5 诊室 0 号机，不代表下次还是——诊室按当天开诊顺序排，你得看大屏。
>
> ② 不懂的人会怎么错想：会以为 `hw:0,0` 是"第一个麦克风"、`hw:1,0` 是第二个，以为自己插的顺序决定编号；或者以为 ALSA 会聪明地替你挑。于是代码里硬写 `hw:0,0`，换台机器就跑不起来。
>
> ③ 一句话戳破：逗号前那个数是**内核枚举出来的声卡身份证号**，逗号后是**这张卡内部的 PCM 编号**，两个都不是你能定的常量——只能查出来再填。
>
> ④ 回到术语：写法是 `hw:CARD,DEV`。CARD 对应 `/proc/asound/cards` 里的 index，DEV 对应卡内 pcm 设备（采集是 `/dev/snd/pcmC5D0c`，那个 `c` 就是 capture）。`hw:` 前缀的意思是绕过 dmix、plug 直接跟硬件说话，延迟可控，代价是采样率和格式必须硬件原生，不匹配就返回 `-EINVAL`，这时才退到 `plughw:`。

### Q：hw:5,0 这种写法到底是什么？为什么不是 hw:0,0？

**一句话答案：** 它是 ALSA 的 PCM 设备名，逗号前是声卡编号、逗号后是卡上设备编号。5 不是"第五个插口"，0 也不是"第一个设备"，两个数都是内核按枚举顺序分配的。板载 codec 和 HDMI 音频先占了号，你的第一张 USB 声卡自然就不是 0。

**展开讲：** 三种写法要能当场分清：

| 写法 | 含义 | 什么时候用 |
| :--- | :--- | :--- |
| `hw:5,0` | 第 5 张卡的第 0 个 PCM 设备，绕过软件转换 | 要低延迟、参数硬件原生支持 |
| `plughw:5,0` | 同上，但中间插一层 plug 做重采样和格式转换 | 硬件不支持你要的 16 kHz 或 S16_LE |
| `default` | 走系统默认设备，通常经过 dmix 或音频服务 | 只想出声，不关心延迟 |

查的三条命令，面试时可以顺口说出来：

```
arecord -l                                                # 列出采集设备，看 card N 与 device M
cat /proc/asound/cards                                    # card index 与 id 的对应关系
arecord -D hw:5,0 -f S16_LE -r 16000 -c 2 -d 5 t.wav     # 录 5 秒验证
```

代码侧就是 `snd_pcm_open(&handle, "hw:5,0", SND_PCM_STREAM_CAPTURE, 0)`，失败看返回值。

**如果被追问「为什么不能一直用 plughw？」：** 因为 plug 会做重采样和格式转换，多一层路径就多一层延迟和一次缓冲，转换本身还有精度损失。能原生就原生。

**如果被追问「打开失败报什么？」：** 三种最常见：`-ENOENT` 是没这个设备（号写错），`-EBUSY` 是被别人占着，`-EINVAL` 是参数硬件不支持。`-EINVAL` 别猜，用 `arecord --dump-hw-params -D hw:5,0` 把硬件支持的 rate、format、channel 全列出来。

### Q：简历写"数据面 TCP 9000 与控制面 HTTP/RPC 8088 解耦"，为什么要分两个端口？

**一句话答案：** 因为这两个面的用户、时限和故障后果完全不同。9000 是数据面，一路定长帧按固定节奏往外推，谁跟不上就丢帧；8088 是控制面，一次请求一次应答，可以慢但必须答对。把两条命分开，一条堵死不会把另一条带下水——哪怕 9000 被不读数据的客户端拖住，你还能通过 8088 把报警灯关掉。

**展开讲：** 两个面的设计目标几乎相反，这才是解耦的真正理由。9000 只干一件事：别积压。248 字节定长帧，10 个框上限，队列容量压得很小，满了丢最旧，建联瞬间清空存量，判据是延迟。8088 只干一件事：答得对。`GET /api/status` 读 7 个温区、NPU 三核负载、`/proc/meminfo`；`POST /api/led` 写 `/sys/class/leds/work/` 下的 trigger 和 brightness；`GET /api/vision` 去 9000 取一帧采样。判据是内容正确，几十毫秒完全可以接受。

代价也要主动说，这才叫懂：8088 取一帧是**真的以 TCP client 连 127.0.0.1:9000**，不是同进程函数调用。于是多了一次往返，而且必须自己处理短读——代码里是 `while (received < sizeof(res)) recv(...)`，配 1 秒的 `SO_RCVTIMEO`，收不满就返回 incomplete。这是解耦的账单。

**如果被追问「127.0.0.1 也走 TCP，不浪费吗？」：** 浪费，但换来的是两块能分别重启、分别部署、分别限流。要不要付这个代价，看你更怕性能还是更怕耦合。我这个场景控制面是"人手点一下"的频率，一次往返可以直接忽略。

**如果被追问「控制面自己会不会被打爆？」：** 会，我没做限流，这是明确缺口。要补就是连接数上限或者令牌桶。代码里 8088 用了 `MSG_NOSIGNAL`，说明我至少想到了写失败不能杀进程，但没想到"请求太多"这一层。

### Q：简历技能栏写了"现代 C++（RAII、智能指针、移动语义）"，但项目里你真用上了吗？

**一句话答案：** 用上了三样里的两样半：`unique_ptr` 真用了（PImpl 和编码器池），移动语义真用了（队列里搬大对象），RAII 是**间接**用的（靠标准库容器和 `unique_ptr` 的析构，没自己写 guard 类）。没用的是 `shared_ptr`（全仓库零使用）、模板和 STL 算法。这个边界我主动说，比被挤出来好，因为考官下一步八成问 `shared_ptr` 的引用计数。

**展开讲：** 被问"真用上了吗"，最差的答法是"用了用了"再举一个背出来的例子。最好的答法是给一张位置表，每条都能指到文件行。

| 简历写的 | 项目里出现在哪 | 程度 |
| :--- | :--- | :--- |
| RAII | `std::vector` 与 `std::unique_ptr` 的析构自动释放；模型文件读进 `std::vector<char>`，退出不用手写 `free` | 理解到位，没手写 guard 类 |
| `unique_ptr` | `rknn_engine.h:20` 的 `std::unique_ptr<Impl> pImpl;`；`mpp_jpeg_encoder.h:216` 的 `std::vector<std::unique_ptr<MppJpegEncoder>> encs_;` | 真用了 |
| `shared_ptr` | 全仓库没有 | 只在学的时候写过 |
| 移动语义 | `g_raw_queue.push(std::move(raw_frame))`、`frame = std::move(g_raw_queue.front())`、`g_latest_jpeg = std::move(jpg)` | 真用了 |
| STL | `std::vector`、`std::queue`、`std::string`；算法只到 `min`、`max`、`sort` | 会用，不算熟 |
| 模板 | 没写过自己的模板库 | 没做 |

一句话总结这个边界：**"我用的智能指针是 `unique_ptr`，不是 `shared_ptr`"**——说出去考官觉得你诚实；不说而被问出来，他会觉得你在凑关键词。

**如果被追问「RAII 没手写 guard，凭什么说会？」：** RAII 的判据不是"你写过几个类"，是"资源释放有没有写进析构函数"。标准库已经替我做完了，我能说清自己写要注意什么：拥有资源的类禁拷贝只留移动，析构不能抛，移动后源对象要留在合法状态。

**如果被追问「模板为什么不写？」：** 没场景。三个 NPU worker 是同一个类实例化三次，不需要类型参数化；硬写模板反而暴露没工程判断。

### Q：RAII 到底是什么？为什么它是 C++ 和 C 最大的差别？

**一句话答案：** RAII 就是把"释放资源"绑在"对象销毁"上——构造里拿资源，析构里还资源，剩下的交给栈。函数怎么退出都不重要（正常 return、提前 return、抛异常），只要对象在栈上，析构一定跑。C 里释放资源靠"我记得还"，C++ 里靠"语言保证会还"。

**展开讲：** 对比着看最清楚。C 的手工路径是 `open`、`malloc`，中间任何一个提前返回忘了 `close` 就是泄漏。C++ 里 `std::ifstream`、`std::vector`、`std::unique_ptr`、`std::lock_guard` 全是 RAII，你什么都不用记。

我项目里能指到位置的两处：`rknn_engine.h` 里的 `pImpl` 让头文件不必暴露 RKNN 的头文件，析构写在 `.cpp` 里，那里才看得见完整类型；模型文件读进 `std::vector<char>`，退出自动释放。

三个细节要说出口：析构函数不该抛异常（栈展开中再抛直接 `std::terminate`，C++11 起析构默认 `noexcept`）；拥有资源的类必须禁拷贝或写移动，否则双重释放；`lock_guard` 的作用域就是锁的作用域。还有一个反例：`flock` 那个单实例锁我故意不 `close`，让它随进程退出由内核释放——这**不是** RAII，是拿内核语义当兜底。

**如果被追问「析构函数里能抛异常吗？」：** 不能。栈展开过程中再抛就是 `std::terminate`；而且析构默认 `noexcept`，你写了 `throw` 程序就死。

**如果被追问「RAII 比 GC 好在哪？」：** 确定性。GC 什么时候回收不确定，RAII 在离开作用域那一刻就确定回收。fd、锁、设备句柄这类有限的系统资源，你等不起一次不确定时机的 GC。

> 【费曼讲解】RAII 为什么是"纪律"而不是"工具"
>
> ① 生活类比：酒店房卡。入住时前台把卡给你，退房时自动注销。你中途从后门溜出去，酒店照样在退房时间把卡注销——"退房"不依赖你记不记得。
>
> ② 不懂的人会怎么错想：会以为 RAII 就是"用智能指针"，或者"用完记得 `delete` 就叫 RAII"。错在把一条语言规则当成了一个库功能。也常有人以为写在函数末尾的 `cleanup()` 算——那个不算，它只在"走到那一行"时才执行。
>
> ③ 一句话戳破：判据只有一条——**资源的释放有没有写进某个对象的析构函数**。写了就是，没写就不是，跟用不用智能指针无关。
>
> ④ 回到术语：全称 Resource Acquisition Is Initialization，直译"资源获取即初始化"，但真正的重点在那句没写出来的后半句——"资源释放即析构"。C 靠程序员自律，C++ 靠作用域规则，这就是两种语言的资源模型差异。

### Q：智能指针 unique_ptr 和 shared_ptr 该用哪个？你的多线程队列里怎么用的？

**一句话答案：** 默认 `unique_ptr`——独占所有权、零额外开销、能表达"这东西只有一个主人"。只有当你真说不清谁最后用完、所有权必须画成图的时候，才用 `shared_ptr`，并且接受引用计数的原子开销和循环引用风险。我项目里只有前者，因为资源全是一个主人；队列里放的甚至不是指针，是值。

**展开讲：** 判据一句话：所有权能画成树就用 `unique_ptr`，必须画成图才考虑 `shared_ptr`，而且优先用 `weak_ptr` 打断环。

两个真实用法。PImpl：头文件里只留 `std::unique_ptr<Impl> pImpl;`，RKNN 的 include 全藏在 `.cpp`，析构必须在 `.cpp` 里定义，否则报"incomplete type"——这个报错就是最常被问的细节。编码器池：`std::vector<std::unique_ptr<MppJpegEncoder>> encs_;` 配 `encs_.push_back(std::move(e));`，三个实例，vector 存独占所有权，对象里含 MPP context 根本不该拷贝。

队列里怎么用的才是重点：队列里放的是**值**，不是指针。生产者 `push(std::move(raw_frame))`，消费者 `frame = std::move(g_raw_queue.front())`。为什么不用指针？定长结构体本身可移动，用指针反而多一次堆分配、多一个所有权问题、多一次间接访问。**能不分配就别分配。**

| | `unique_ptr` | `shared_ptr` |
| :--- | :--- | :--- |
| 占多大 | 一个指针 | 两个指针，对象加控制块 |
| 能不能拷 | 不能拷，只能 move | 能拷，引用计数原子加减 |
| 运行时开销 | 零 | 每次拷贝一次原子操作 |
| 典型误用 | `new` 之后忘了包 | 循环引用永不释放 |

**如果被追问「`shared_ptr` 的引用计数线程安全吗？」：** 计数本身是原子的，两个线程各拷一份不会算错；但**指向的对象不是**，两个线程同时改 `*p` 一样要加锁。两句话说完就够。

**如果被追问「为什么不用 `make_unique`？」：** 用，应该用。它解决两件事：异常安全（避免 `new` 成功而 `unique_ptr` 构造失败），以及不用重复写类型名。

### Q：移动语义解决了什么问题？std::move 到底 move 了什么？

**一句话答案：** 解决的是"临时对象被白白拷贝一遍"。`std::move` 本身**一个字节都没搬**——它只是把左值强制转成右值引用，相当于贴一张"这个对象我不要了，你可以掏空它"的标签；真搬东西的是移动构造或移动赋值。

**展开讲：** 我项目里三个位置，全是"大对象要换主人"：`g_raw_queue.push(std::move(raw_frame))`，一帧是 720p 图像数据，拷一次就是几 MB 的 memcpy；`frame = std::move(g_raw_queue.front())`，从队头掏出来，后面 `pop()` 只销毁空壳；`g_latest_jpeg = std::move(jpg)`，共享槽换掉旧值。还有"按值收、move 存"：`HttpPreview::HttpPreview(int port, std::string title) : port_(port), title_(std::move(title)) {}`，传左值传右值都行。

三个必须说清的点。第一，移动之后原对象是"合法但未指定"，只能赋值或析构；`unique_ptr` 移动后变 `nullptr` 是标准明确保证的，`std::string` 移动后不保证为空。第二，`std::move` 一个 `const` 对象会**静默退化成拷贝**，因为 `const T&&` 绑不到 `T&&`。第三，`return std::move(x)` 是负优化，它抑制了返回值优化。

**如果被追问「哪些类型 move 了跟没 move 一样？」：** 没写移动构造、也没写移动赋值的类型会退化成拷贝，不报错、不警告。所以"我加了 `std::move` 就快了"必须靠实测。

**如果被追问「为什么栈上小对象 move 没意义？」：** 收益来自"接管资源"，比如指针、堆内存、文件句柄。三个 `int` 组成的结构体没有资源可接管，代价一样。

> 【费曼讲解】`std::move` 什么都没搬
>
> ① 生活类比：搬家。拷贝是"照原样再做一套家具放进新房"，移动是"把家具直接抬过去，旧房空着"。`std::move` 不是搬家工人，它是**搬家许可证**——只负责盖章说"这套可以搬了"，真动手的是移动构造函数那个工人。
>
> ② 不懂的人会怎么错想：以为调完 `std::move(a)` 之后 `a` 就空了、以为 `std::move` 自己执行搬运、以为写了 `std::move` 就一定比拷贝快。前两个是理解错，第三个在类型没有移动构造时会**静默**退化成拷贝。
>
> ③ 一句话戳破：`std::move` 只是把实参的值类别从左值改成右值，好让重载决议选到那个"拿走你东西"的构造函数；标签贴错了（对象是 `const`、类型没写移动构造），该拷还是拷，而且一声不响。
>
> ④ 回到术语：`std::move` 的实现就是 `static_cast<T&&>(x)`，一个类型转换，不产生任何机器码。移动语义的完整链条是三样东西：右值引用 `T&&` 提供语言机制、移动构造和移动赋值提供实现、`std::move` 提供把左值标成右值的工具。

### Q：简历写"V4L2 双路 1280×720 摄像头，定位出代码未显式请求帧率导致默认协商到 20fps"，这个 bug 怎么发现的？

**一句话答案：** 不是我盯着代码看出来的，是"实际节奏和声明节奏对不上"逼出来的——代码里写的是 30，实测每帧 50 ms，正好 20 fps。三步定位：先证明硬件支持 30（`v4l2-ctl --list-formats-ext` 列出 1280×720 MJPG 的 `Interval: Discrete 0.033s (30.000 fps)`）；再看运行时到底协商成了什么（`--get-parm` 报 `Frames per second: 20.000`）；最后回源码搜"谁设了帧率"——三处代码都只设了 FOURCC 和分辨率，一处都没设帧率。

**展开讲：** 这个 bug 值钱的地方不是结论，是"回读会骗人"这第二层。我显式请求 30，回读 30.00，实测 33.32 ms 一帧，正常；但我又试了请求 25，**回读同样是 25.00，实测却还是 50 ms 一帧**。`--get-parm` 回读的只是软件层期望值，真值只能用帧间隔量。

修复后的验收是 400 帧长测：两台设备均值都是 33.33 ms，p95 分别是 33.50 和 33.39，最大偏差 0.76 ms。为什么敢说零抖动？因为均值和 p95 只差 0.17 ms，不是只看均值好看。

**如果被追问「400 帧够吗，怎么排除偶然？」：** 两台设备各 400 帧，看的是 p95 和最大偏差，不是只看均值。均值 33.33、p95 33.50、最大偏差 0.76 ms，三个数一起才叫"零抖动"。

> 【费曼讲解】帧率为什么"设了"不等于"就是"
>
> ① 生活类比：你跟水管工说"我要每分钟 30 升"，他点头说"好的，30"。你回家一量，20 升。回去问他，他指着本子说"你看我这儿写着 30 呢"。本子上写的是他的打算，水表上走的才是真的。
>
> ② 不懂的人会怎么错想：会以为"代码里 `cap.set(CAP_PROP_FPS, 30)` 了，那就是 30"，或者以为"回读也是 30 就是 30"。这两层都只是"意愿"，而帧率是硬件和驱动**协商**出来的第三层，只有帧间隔能证明。
>
> ③ 一句话戳破：能证明帧率的只有一个量——两个时间戳之间的距离。其他任何"设置成功""回读一致"都只是声明，不是事实。
>
> ④ 回到术语：V4L2 里分辨率走 `VIDIOC_S_FMT`，帧率走 `VIDIOC_S_PARM` 的 `timeperframe`，分子分母两个整数。OpenCV 的 `CAP_PROP_FPS` 最终也落到 `S_PARM` 上，但它**不检查返回值**，所以设置失败了你也不知道。判据只能是采 N 帧记首尾时间，或者读每帧 `v4l2_buffer.timestamp` 求间隔。

### Q：有限状态机（FSM）设计，你那个 5s 周期巡检状态机是怎么写的？迟滞判决是什么？

**一句话答案：** 状态机就是把"现在是什么状态、满足什么条件换到哪个状态"写成一张明确的表，而不是散在一堆 `if` 里。我那个守护是三态、5 秒一个采样周期；迟滞判决是给"进"和"出"配不同阈值加不同连续次数——人：连续 2 个周期 score ≥ 0.5 才进，连续 5 个周期没有人才出；温度：`zone0 > 75.0°C` 瞬时进，`zone0 < 70.0°C` 连续 3 个周期才出，中间那 5°C 是迟滞带。

**展开讲：** 三个设计决定，每个都能被追问。一是阈值要两套：进出都用 75 的话，温度在 75 上下抖一下就会反复告警和恢复，灯闪个不停、日志刷满，值班的人很快就学会忽略它。用进 75、出 70，等于在中间开一条"不许改主意"的缓冲带。最能说明问题的一行是 `thermal_clear = 0;`——迟滞带内既不触发新告警，也不计入恢复。

二是"进"瞬时、"出"要连续 3 个周期：巡检场景漏报比误报贵，进的方向单点触发，宁可多响一次；出的方向连续确认，防一次读数抖动就把告警撤了。三是 person 和 thermal 是两个**独立的子状态**，各有 active 标志和计数器；`overall` 只是给日志和 LED 用的展示值，优先级 `PERSON_ALERT > THERMAL_ALERT > NORMAL`，这样两个告警同时成立不会互相覆盖。骨架一行：

```
enum PatrolState { ST_NORMAL = 0, ST_PERSON = 1, ST_THERMAL = 2 };

int overall = person_active ? ST_PERSON
            : (thermal_active ? ST_THERMAL : ST_NORMAL);
```

还有 fail-safe 必须讲：采样失败时**冻结计数器，不翻转状态**。读不到温度不等于温度正常，连不上视觉不等于没人。

**如果被追问「5 秒是不是太慢，简历还写毫秒级响应？」：** 5 秒是采样周期，不是响应时间。周期内一次视觉探测给了 300 ms 超时，占一个周期不到 6%，事件判定就在这个探测里完成——"毫秒级"指单次探测。温度的时间常数是分钟级，缩到 1 秒只会让 sysfs 读取量涨 5 倍。

> 【费曼讲解】迟滞判决为什么不是一个阈值
>
> ① 生活类比：小区门口的闸机。进门不用刷卡，来人就开；出门必须刷卡，确认才放。如果进出同一个规则、门按"有没有人"开关，那有人在门口站着不动、身体前后微晃，闸机就开开关关咔咔响。迟滞就是给"开"和"关"各配一条线，晃不出那两条线就不许动。
>
> ② 不懂的人会怎么错想：会以为"阈值就是一个数，超过告警、低于恢复"，觉得两个数是多余讲究；或者把迟滞理解成"防抖"，以为它只是让日志好看一点。
>
> ③ 一句话戳破：一个阈值管两个方向，等于把"判决"变成了"跟随"——输入抖一下输出就抖一下。迟滞的代价是引入一小段"我不表态"的区间，换来的是输出对输入噪声不敏感。
>
> ④ 回到术语：这是施密特触发器的软件版，上阈值与下阈值之间是保持带，只有跨出带外才改变输出。工程实现就是两个条件分支加两个计数器，比"当前值和上次值差超过某个量"稳得多，因为后者在缓慢漂移时会一路误判。

### Q：GDB 你说会用，具体用 GDB 定位过什么问题？（诚实版答法，别吹）

**一句话答案：** 只真正用过一次，但那次是完整闭环：MPP 硬编时 `encode_put_frame` 直接段错误，`gdb` 打出栈，崩在 MPP 内部的断言上，断言信息是 `cfg->fps_in_denom >= 1 failed at rc_frm_check_drop:142`——FIXQP 模式下 fps 分母是 0 导致除零，设成 1 就好了。除此之外 `strace`、`dmesg`、`/proc/interrupts`、`ldd`、`fuser`、`ss`、`taskset`、`errno` 是真用过；`valgrind` 和 Linux `perf` 我在这块板上没跑过。

**展开讲：** 为什么要主动画边界？因为 GDB 是"越问越深"的话题，`break`、`bt`、`frame`、`info locals` 谁都会背，考官真正想看的是"你有没有在真出问题的时候靠它救过命"。一次真实案例加一条明确边界，比背十条命令有说服力。

那次的过程值得讲清：程序不是慢慢错，是一调就崩。`gdb ./程序` 进去 `run`，崩了 `bt`，栈里最上面几帧在 `libmpp` 里，下面是我自己的调用。但真正解决问题的不是栈顶，是**断言消息里的文件名和行号**——`rc_frm_check_drop:142` 直接告诉你是哪个前置条件没满足。这个细节能证明我理解"断言比栈顶更有信息量"。

边界要背熟：GDB 会用但不算熟；`valgrind` 没跑过（板子是 aarch64，还没交叉编过去）；`perf` 没跑过，逐层剖析用的是 RKNN 自己的 `PERF_DETAIL`。这么说考官不会白费时间往深里问。

**如果被追问「`bt` 出来的栈看不懂怎么办？」：** 先看最上面那帧是不是在自己代码里。全在库里的话栈没用，转去看断言、`errno`、日志，再回头查自己传进去的参数——那次就是这么解的。

### Q：简历写"进程生命周期管理（文件描述符与管道资源治理）"，指的是什么事？

**一句话答案：** 指的是一次真踩的坑：给 LED 爆闪起的那个长寿子进程继承了父进程的 stdout 和 stderr 管道写端，父进程跑完了，上游永远等不到 EOF——一个本该 21 秒返回的回归用例卡死 270 秒被强杀。修法是在 `execl` 之前把 0/1/2 全部重定向到 `/dev/null`。

**展开讲：** 现象太好认了：板上 `ps` 看进程已经没了，灯也真的在闪（功能完全正确），但调用方的命令不返回；交互式 ssh 秒回，只有"抓 stdout"的场景卡死。这个对比就是 fd 继承的指纹。

机理值得背下来：管道是引用计数资源，读端要等到**所有写端都关闭**才返回 0。`fork()` 把子进程的 fd 表整份复制，那个长寿的 `sh -c` 循环手里握着同一个写端，所以读端永远等不到 0。父进程退出不改变这件事，因为引用还在。

修的位置在 `lab/agent/edgevision_patrol_daemon.cpp` 的 `led_alarm_start()`：`fork` 之后子进程先 `setsid()`，再 `open("/dev/null", O_RDWR)` 拿一个 fd，三个 `dup2` 把 0/1/2 盖掉，最后才 `execl`。为什么是 `dup2` 到 `/dev/null` 而不是 `close`？因为子进程后面还会写（`sh` 的报错、`sleep` 的 stderr），关掉 1/2 会让它写到随机 fd 上。

"生命周期管理"具体长什么样，就藏在这套动作里：启动先做一次幂等清场（把上一轮的 alarm 进程停掉），写 pid 文件；停止时 `kill(pid, SIGTERM)`，最多等 200 ms（20 次 10 ms），还活着就 `SIGKILL`，然后 `unlink` pid 文件；最后兜底把 trigger 和 brightness 写回安全值；`fork` 之后还用 `kill(pid, 0)` 探活。**启动有清场、停止有优雅期和兜底、任何一步失败都有退路。**

同一个根因还有第二个形态：另一次是 fork 出来的子进程继承了 NPU 的 mmap 映射，父进程退出后 NPU 内存释放不掉，`rkllm_init` 报 `malloc npu memory 205799424B, errno 14 (ENOMEM)`，而 `free` 还有 6 GB 富余。对照实验一做就清楚——`fork` 之后立刻 `execl()` 重建地址空间，NPU 恢复正常。**`fork` 的语义是克隆，不是"启动一个干净的新程序"。**

**如果被追问「`fork` 和 `exec` 之间能做什么？」：** 只能做 async-signal-safe 的动作，`dup2`、`exec*`、`_exit` 这些；不能 `printf`、不能 `malloc`、不能碰锁。

**如果被追问「怎么保证不留僵尸或孤儿？」：** 双保险：pid 文件加 `kill(pid, 0)` 探活；真成了孤儿也会被 init 或 systemd 收养，因为它已经 `setsid` 过，不在我的进程组里。

## 四、这一章的"记忆锚点"

- **`hw:5,0` 不是"第五个麦克风"**：card 是内核枚举的声卡号，device 是卡内 PCM 号，只能查出来再填。
- **`hw:` 直连，`plughw:` 走 plug**：参数硬件不支持时才退到后者，别硬顶到 `-EINVAL`。
- **RAII 的判据只有一条**：资源释放有没有写进析构函数？写了才算。
- **`std::move` 一个字节都不搬**：它只贴标签，真搬的是移动构造。
- **默认 `unique_ptr`，`shared_ptr` 得要个理由**：所有权能画成树，就别画成图。
- **能证明帧率的只有帧间隔**：`set` 和回读都只是意愿，请求 25 回读 25 实测 20 就是证据。
- **迟滞等于两套阈值加两个计数器**：一个阈值管两个方向，判决就退化成跟随。
- **进要快、出要稳**：漏报比误报贵，所以进单点触发、出连续确认。
- **`fork` 只克隆，`exec` 才换人**：长寿子进程进执行前把 0/1/2 重定向到 `/dev/null`。
- **Linux 考官不一定懂 AI，但一定懂 Linux**：这一章的重点是基本功，不是 NPU。
