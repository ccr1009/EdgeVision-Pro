# 附录 速查表

## 附录怎么用

这份附录不指望你从头读到尾，它是**考前工具的集合**，按场景分四块用。

第一块是数字墙，用途是**核对**：你准备的所有说法里出现的每个数字，都必须能在这五张表里找到一模一样的写法。找不到出处的数字，一律不要说。第二块是命令墙，用途是**现场复现**：面试官问"这个数你怎么测的"，你能当场把命令写出来，可信度立刻不同。第三块是术语表，用途是**开口不卡**：自我介绍和追问环节会用到大量术语，说不利索会显得不熟。第四块是一周清单和考前十分钟速览，用途是**安排节奏**。

三条硬规矩。第一，数字墙里的数字**一个字都不要改**，包括小数位、单位、括号里的补充说明。第二，遇到表里标着"未测""未实现"的项，宁可说"没做"，也不要临时编一个数。第三，讲延迟必须带口径——bench 口径和全链路生产口径是两个数，混着说一定会被追问穿。

**余弦相似度 0.99651 的正确用法**：它是反面教材，不是精度成绩。旧合成色块校准集训出来的模型，cls 分支整体塌缩成常数 0.5（等于 sigmoid(0)）、分类头彻底失效，而它当时的特征图余弦相似度恰好还有 0.9965。换成真实校准集后，9 张真实图 top-1 平均分从 0.5000 升到 0.8072（FP32 是 0.8125）。面试讲法：「我一开始也拿余弦相似度当精度指标，0.9965 就 PASS 了；后来发现这个数会骗人——特征图整体相似不影响单个分支塌缩。真精度得跑 mAP，COCO128 上 929 个 GT 框测出来 0.6087 到 0.6002，−1.4%。」

**两处容易被抓的口径混用**：一是延迟，bench 口径 20.58 毫秒 / 48.6 FPS 不含解码和 CSC，生产链路 55.84 毫秒 / 17.9 FPS 含 CSC，另一个早期上位机口径是 19.2 FPS；二是模型体积，12.2 MB 的 FP32 ONNX 到 6.22 MB 是量化这一步（−49.2%），6.22 MB 到 4.34 MB 是图手术这一步（−30.2%），不能合成一句"从 12.2 降到 4.34"。

## 二、命令墙

**板端编译与运行**

```bash
ssh rk3588
cd /root/edgevision/deploy/cpp && mkdir -p build_native && cd build_native
cmake .. -DCROSS_COMPILE_RK3588=ON && make
cd /root/edgevision && ./deploy/cpp/build_native/edgevision_pro_rknn
```

**性能探针：单核、三核、逐层剖析**

```bash
B=/root/edgevision/deploy/cpp/3rdparty/rknn_api
g++ -O2 -std=c++17 bench_npu.cpp -I$B/include -L$B/lib -lrknnrt -o bench_npu
g++ -O2 -std=c++17 bench_multicore.cpp -I$B/include -L$B/lib -lrknnrt -pthread -o bench_multicore
export LD_LIBRARY_PATH=$B/lib
./bench_npu <model> 200        # 单核 / 三核 / 延迟分位数
./bench_npu <model> 1 --perf   # 逐层耗时剖析，靠 RKNN_FLAG_COLLECT_PERF_MASK
./bench_multicore <model> 100  # 三独立 context 并行
```

跑生产链路 A/B 时库路径要把 MPP 也带上，并且固定大核，否则均值会骗人：

```bash
export LD_LIBRARY_PATH=/root/edgevision/deploy/cpp/3rdparty/rknn_api/lib:/root/edgevision/third_party/mpp/lib
taskset -c 6 ./deploy/cpp/build_native/edgevision_pro_rknn <图片> 
```

**systemctl 常用**

```bash
systemctl status edgevision          # 看是否开机自启、是否 5 秒自愈
systemctl restart edgevision
systemctl enable edgevision          # 建开机自启链接，重启生效
journalctl -u edgevision -f          # 跟日志
systemctl list-units --type=service  # 看当前有哪些服务
```

**排查三板斧：strace、perf、中断**

```bash
strace -f -p <pid>                  # 跟系统调用，看卡在哪个 fd
strace -c ./prog                    # 统计各系统调用耗时占比
perf top                            # 看热点函数
perf stat -e cache-misses,cycles ./prog
ss -lntp                            # 端口被谁占着
fuser /dev/video81                  # 设备被哪个进程占
ldd ./binary                        # 链了哪些库、路径对不对
free -h ; df -h                     # 内存 7.5Gi / eMMC 57.6G 口径
```

看「是不是真的走了硬件」时不去猜，直接看中断增量：

```bash
grep -E 'jpege|rga|rknpu' /proc/interrupts
cat /sys/kernel/debug/rknpu/version
cat /sys/class/devfreq/fdab0000.npu/cur_freq
cat /proc/interrupts | grep mpp
```

## 三、术语表

每条一句话，能在面试里顺口说出来就行。

| 术语 | 一句话解释 |
|---|---|
| fd | 进程持有的文件描述符，本质是内核文件表的下标 |
| 系统调用 | 用户态主动陷入内核要服务的唯一正规入口 |
| fork / exec | fork 复制出子进程，exec 用新程序覆盖当前进程的地址空间 |
| 僵尸进程 | 已退出但父进程没 wait，只剩一条进程表记录 |
| 孤儿进程 | 父进程先死，被 init 或 subreaper 收养 |
| pthread | POSIX 线程库，Linux 上就是 NPTL 的那套接口 |
| mutex | 互斥锁，保证临界区同一时刻只有一个执行流 |
| 条件变量 | 让线程睡在某个条件上，由别人唤醒，必须配 mutex 且用 while 判条件 |
| 虚假唤醒 | 没有任何人 signal 也可能醒，所以条件判断必须写 while 不能写 if |
| 原子操作 | 单条指令完成、中间不可能被别人插进来读写的操作 |
| 内存序 | 规定多核下读写重排允许到什么程度，比如 acquire 和 release |
| epoll | 内核维护红黑树加就绪链表的事件通知机制，只返回就绪的 fd |
| LT / ET | 水平触发没读完会继续通知，边缘触发只通知一次必须读到 EAGAIN |
| 非阻塞 IO | 读不到立刻返 -1 并置 EAGAIN，不是错误只是现在没有 |
| 粘包 | TCP 是字节流没有消息边界，一条连接上两次 send 可能一次 recv 收到 |
| 背压 | 下游处理不过来时向上游反馈，让上游减速或丢帧，避免无界队列撑爆内存 |
| SO_REUSEADDR | 允许绑定处于 TIME_WAIT 的端口，重启服务不报 Address already in use |
| TIME_WAIT | 主动关闭方等 2MSL，保证最后的 ACK 能重传、旧包不串到新连接 |
| 守护进程 | 脱离终端后台长跑，经典三步是 fork 后父退、setsid、重定向 0 1 2 |
| systemd | 现代 Linux 的服务管理器，管开机自启、崩溃重拉、日志收集 |
| SoC | 片上系统，CPU、GPU、NPU、编解码器全在一块芯片上共享内存总线 |
| NPU | 神经网络加速器，靠大规模乘加阵列做定点卷积，RK3588 上是 3 核 |
| RKNN | 瑞芯微的模型格式与推理框架，把 ONNX 转成能在 NPU 上跑的 rknn |
| context | 一次模型加载得到的推理上下文，独立 context 才能各自绑一个核 |
| core mask | 指定这个 context 只在哪几个 NPU 核上跑，硬绑 0 1 2 才是真并行 |
| RGA | 瑞芯微的 2D 图形加速器，做缩放和格式转换，但本板不支持 full CSC |
| MPP | 瑞芯微媒体处理平台，做硬件编解码，本项目用它硬解 MJPEG 到 NV12 |
| DMA-BUF | 让不同硬件模块共享同一块缓冲区、传 fd 不拷贝的内核机制 |
| letterbox | 等比缩放后补灰边到目标尺寸，避免拉伸改变长宽比影响检测 |
| NMS | 非极大值抑制，按分数排序后压掉与高分框 IoU 过高的重复框 |
| DFL | 分布焦点损失，YOLOv8 检测头里把四个边做成 16 个 bin 再求期望 |
| mAP | 平均精度均值，检测任务的真实精度指标，比余弦相似度可信得多 |
| INT8 / 量化 / scale / 校准集 | 把浮点权重压成 8 位整数，scale 决定数值映射范围，校准集决定 scale 怎么取 |
| W8A8 | 权重和激活都是 8 位整数，端侧大模型常用的量化方案 |
| RKLLM | 瑞芯微的大模型推理运行时，负责在 NPU 上跑量化后的语言模型 |
| ReAct | 推理加行动的循环范式，模型先想一步再做一次工具调用再看观察结果 |
| Tool Calling | 模型按约定格式输出工具名和参数，由宿主程序真正执行 |
| Observation | 工具执行结果回填给模型的那段内容，必须是合法 JSON 才好解析 |
| 占空比 | 一个周期里高电平所占比例，本项目用它判定 LED 是否真的在闪 |
| 故障注入 | 主动把服务停掉、把设备拔掉来验证系统的降级和恢复是否真的有效 |

## 五、面试前一晚的十分钟速览

进场前只看这十条，不要再翻长篇。

1. 项目一句话：RK3588 上从摄像头到 NPU 到推流的完整视觉链路，外加一个纯板端离线的具身 Agent，全部真实闭环。
2. 三个最有分量的数：纯推理 15.95 毫秒、单帧全链路 20.58 毫秒 / 48.6 FPS、三核 59.3 FPS / 2.21×。
3. 讲三核必须同时说"不是线性 3×，每核负载只有 49%，并行效率 73.5%"。
4. 讲精度必须说"真 mAP，COCO128 上 0.6087 到 0.6002，掉 1.4%"，不许提余弦相似度当成绩。
5. 两个延迟口径别混：bench 20.58 毫秒，生产含 CSC 是 55.84 毫秒 / 17.9 FPS。
6. 五个没做的事记牢：RGA 硬件 CSC、DMA-BUF 零拷贝、RTSP 与 WebRTC、H.264 与 H.265 硬解、ByteTrack 进 C++ 链路。
7. 两个没测的事：整机功耗没测过，语音入口只做了选型没实测。
8. 被问倒的三步：先确认问题、给最接近的答案、明确划边界。
9. 三个杀手故事：37 毫秒拆到 125 个算子、余弦 0.9965 骗了我、演示全绿但 Agent 在说假话。
10. 最后一句永远是：我清楚自己做到哪一步，也知道下一步该补什么。

### 一句话用法

面试时简历摊在桌上，你的眼睛不要一直看简历——但**心里要有这张表**：面试官的手指落在哪一行，你脑子里立刻应该跳出"这是第几章、我怎么讲、边界在哪、他最可能追什么"。

## 七、十二句不能说错的话（口径对照表）

这一节是全书**最容易被抓包**的地方。同样的数字，说法差一个字，性质就从"做过的人"变成"背过的人"。

| 不能说 | 要说 | 为什么 |
|---|---|---|
| INT8 量化 mAP 只掉了 0.85% | 掉 0.85 **个**百分点，从 0.6087 到 0.6002，相对降 1.4% | 0.85 是绝对差，写成百分比是概念错误 |
| 模型体积缩减 64% | FP32 ONNX 12.2 MB，INT8 量化后 6.22 MB，图手术后 4.34 MB | 12.2 到 4.34 跨了量化和图手术两步，不能合成一个减法 |
| 纯推理提速 57% | 耗时从 37.19 降到 15.95 毫秒，降 57%，等价吞吐 2.33 倍 | 57% 是耗时降幅，不是提速倍数 |
| CSC 加速 1.55 倍，全链路也是 1.55 倍 | 1.549 倍只属于 CSC 这一层；全链路是 76.93 到 55.84 毫秒，降 27.4% | 两个口径混着说，等于自己给自己挖坑 |
| 三核并行提速 3 倍 | 2.21 倍，三核各约 49% 负载 | 说 3 倍会被追问到当场翻车 |
| 特征图余弦相似度 0.9965，说明量化无损 | 那是我最值钱的反例——余弦 0.9965 时分类头已经塌了 | 这是反面教材，不是成绩 |
| 软解提速 8 倍 | 解码 p50 1.03 毫秒，软解 7.76 毫秒，约 7.5 倍 | 真算出来是 7.53，说 8 倍会被验算 |
| 模型加载后内存冗余 6.1 GB | 模型加载后系统**空闲**内存维持 6.1 GB | 6.1 是空闲量，不是剩余容量或冗余量 |
| 二进制小了 63% 所以性能提高了 | 体积只是构建优化的副作用，性能来自编译选项本身 | 体积和性能是两件不相关的事 |
| 帧率 48.6 FPS 是生产帧率 | 20.58 毫秒是 bench 口径；生产二进制含 CSC 是 55.84 毫秒、17.9 FPS | 两个口径必须在同一句话里分清 |
| COCO128 上 mAP 0.6002，工业够用 | 0.6002 是测评集上的数，工业场景还得用现场数据重评 | 数据集边界要主动交代 |
| 零拷贝我做了 | 零拷贝我评估过但没做，因为不是当时的瓶颈 | 没做的事写成做了，是唯一不可挽回的错 |

> 【费曼讲解】为什么"口径"比"数字"还重要？把面试想成**记账**：数字是金额，口径是"这笔钱是收入还是流水"。金额说错 5% 只是误差，口径说错就是造假——面试官不会因为 0.85 还是 1.4 扣你分，但他会因为"你连百分点和百分比都分不清，那你测的是不是也没测明白"而直接给你打低分。所以记住一句：**报数之前先报口径，报完口径再报数。**
