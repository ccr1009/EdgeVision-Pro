## 必背的 11 个数字

这些是**你亲手测出来的**，不是网上抄的。面试时说出来，可信度完全不同。

| 数字 | 含义 | 出处 |
|---|---|---|
| **37.19 ms / 26.9 FPS** | 单核推理（p99 = 40.28ms） | `BENCHMARKS.md` 2.2.1 |
| **35.97 ms（-3.3%）** | 单 context 三核 mask，几乎无收益 | 同上 |
| **59.3 FPS / 2.21x** | 3 独立 context 真并行 | `BENCHMARKS.md` 2.2.2 |
| **19.23 vs 18.44 ms** | NPU 主体 vs CPU 回退，**49% 在 CPU** | `BENCHMARKS.md` 2.2.3 |
| **43.7 / 44.2 / 44.0 ms** | 网关三核稳态，墙钟 4973ms | D20 实跑 |
| **60.3 FPS / 丢 0 帧** | 网关聚合吞吐（有界队列 32） | D20 实跑 |
| **6.22 MB** | INT8 模型大小（旧 84ch 模型） | `ls -l` |
| **4.34 MB** | DFL-Free INT8 模型大小（当前使用） | `BENCHMARKS.md` 2.3 |
| **0.6087 → 0.6002** | **真 mAP@0.5（FP32 → INT8，COCO128）**，掉 0.85 个百分点 / −1.4% | `BENCHMARKS.md` 2.4 |
| ⚠️ **0.99651** | 特征图余弦相似度——**这个数别当精度证据用**，见下方反例 | `TROUBLESHOOTING.md` 第 3 条 |
| **12.2 MB → 4.34 MB（−64%）** | DFL-Free 改造 + 量化后的体积 | `BENCHMARKS.md` 2.3 |
| **247** | 板子在跑进程数（D5 遍历 /proc） | `/root/lab/w1_e5` |
| **1000093** | 2 线程百万次无锁自增的实测结果（丢了 9907 次） | D9 |

> ### 🔥 余弦相似度 0.99651 的正确用法：它是「反面教材」，不是「精度成绩」
> 本项目做过对照实验：旧合成色块校准集训出来的模型，cls 分支整体塌缩成常数 **0.5（= sigmoid(0)）**、
> 分类头彻底失效，而它当时的特征图余弦相似度**恰好还有 0.9965**。
> 换成真实校准集后，9 张真实图 top-1 平均分从 **0.5000 → 0.8072**（FP32 是 0.8125）。
>
> **面试讲法**：「我一开始也拿余弦相似度当精度指标，0.9965 就 PASS 了；后来发现这个数会骗人——
> 特征图整体相似不影响单个分支塌缩。真精度得跑 mAP，我用 COCO128（929 GT 框）测的真实掉点是
> 0.6087 → 0.6002，−1.4%。」这套自打脸的过程比任何一个漂亮数字都更值钱。

## 诚实边界：这 4 件事还不能吹

面试官最爱从这里下刀。**主动说「还没做」，比被问穿强一百倍。**

| 问题 | 现状 |
|---|---|
| 真实图片输入 | ❌ 喂的是灰图，模型输出 0 个框 |
| NMS 后处理 | ❌ 只按置信度过滤，上真图会出重叠框 |
| 真实视频解码（MPP/V4L2） | ❌ 没接，所以「4 路 1080P」讲不出口 |
| 端到端延迟 | ❌ 只测了推理边界，不是「摄像头到屏幕」 |

**正确说法**：「目前验证的是推理引擎和推流链路的性能，真实视频链路是下一步。」
