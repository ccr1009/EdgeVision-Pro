# 第 1 周：文件 IO 与进程

> **一句话**：Linux 里**一切皆文件**，设备、温度、模型都是文件；程序是**进程**，进程能生进程。

---

## 一、心智模型（先记这张图）

```
用户态               内核态
  │
  │ open("xx")  ────►  内核找到 inode，建一个「文件描述符 fd」给你
  │  返回 fd=3  ◄────  3 只是你进程里的一张表的下标
  │
  │ read(fd, buf, n) ─►  内核把数据拷到你的 buf
  │ write(fd, buf, n)─►  内核把你的 buf 拷出去
  │ close(fd)    ────►  内核释放这个下标
```

**关键认知：`fd` 是「下标」，不是指针，不是文件本身。**
`0/1/2` 已经被占了：`0=stdin`、`1=stdout`、`2=stderr`。所以你 `open` 出来的第一个 fd 一般是 **3**。

## 二、八股 Q/A

### 基础 IO

**Q：`open` 的返回值是什么？失败返回什么？**
> 成功返回**最小的可用 fd**（≥3），失败返回 `-1` 并设置 `errno`。所以必须判断 `== -1`，用 `perror` 打出原因。

**Q：`read` 返回 0 是什么意思？**
> **对端关闭 / 文件读完（EOF）**。这是最容易漏的分支。返回 `-1` 才是真出错；返回正数才是真读到字节。
> 注意：`read` **不保证读满**你要求的字节数，可能只读到一部分，要循环。

**Q：`read` 返回 `-1` 且 `errno == EINTR` 怎么办？**
> 被信号打断了，**不是错误，重试就行**。正确写法是 `while (n < 0 && errno == EINTR) 重试;`

**Q：`lseek(fd, 0, SEEK_END)` 能干什么？**
> 拿到文件大小（返回 `off_t`），而且**不影响读**（位置在末尾，要读得再 `lseek` 回去）。
> 注意 `off_t` 是 64 位，`printf` 要用 **`%ld`**，用 `%d` 会截断。

**Q：`stat` 和 `lseek` 测文件大小有什么区别？**
> `stat` 查的是**元数据**，不需要打开文件、不移动读写位置；`lseek` 必须 `open` 之后在 fd 上操作。
> 两者结果应该一致 —— 我用模型文件验过，都是 **6526425 字节**。

**Q：`ioctl` 是什么？为什么不直接用 `read/write`？**
> 是**设备专属的控制通道**。`read/write` 只能传数据流，而「设置终端窗口大小」「读网卡状态」这种**命令 + 参数**的操作，靠 `ioctl(fd, 命令号, 参数指针)` 传。命令号是设备驱动定义的魔数（如 `TIOCGWINSZ`）。

### 进程

**Q：`fork()` 之后发生了什么？返回值为什么有三个？**
> 复制出一个几乎一样的子进程，**父子都从 `fork` 后面继续执行**。
> - 父进程拿到 **子进程 PID**
> - 子进程拿到 **0**
> - 失败返回 **-1**
> 所以代码里用 `if (pid == 0) 子进程逻辑; else 父进程逻辑;`。

**Q：`fork` 复制内存，那不是很慢？**
> 用**写时复制（Copy-On-Write）**。`fork` 只复制页表，父子共享同一份物理内存，**谁写谁才复制**。所以 `fork` 本身很快，`exec` 之后才真正换掉地址空间。

**Q：`exec` 和 `fork` 什么关系？**
> `exec` **不创建新进程**，它把当前进程的**代码段整个替换**成新程序，PID 不变。
> 经典组合：`fork` 出子进程 → 子进程 `exec` 新程序 → 父进程 `wait` 等它。这就是 shell 执行命令的原理。

**Q：什么是僵尸进程？怎么产生的？怎么避免？**
> 子进程**已经死了，但父进程没 `wait` 收尸**，内核要留着它的退出码，于是在进程表里留个 `<defunct>` 的空壳。
> 避免：父进程必须 `waitpid`。我在板上实测捕获过 `<defunct>`，然后 `waitpid` 把它收掉了。

**Q：什么是孤儿进程？**
> 父进程先死了，子进程还活着 → 被 **init/systemd**（PID 1）收养，不会没人管。**孤儿无害，僵尸有害。**

**Q：`waitpid` 的第二个参数能拿到什么？**
> 退出状态。要用 `WIFEXITED` / `WEXITSTATUS` 宏解析 —— **不能直接读**那个整数，高 8 位才是退出码。我实测 `uname` 的退出码是 0。

### 目录

**Q：怎么遍历一个目录？**
> `opendir` 拿 `DIR*` → 循环 `readdir` 拿 `struct dirent*` → `closedir`。
> 必须跳过 `.` 和 `..`，否则死循环。

**Q：`/proc` 是什么？为什么能 `ls`？**
> **虚拟文件系统**，不存在于磁盘，是内核**实时生成**的。每个 `/proc/<pid>/` 是一个进程，`comm` 是进程名。
> 所以 `ls /proc` 就等于看**当前进程表** —— 我做的就是这件事，扫出 **247 个进程**。

## 四、踩过的坑

- **`%d` 打印 `off_t`** → 要 `%ld`，否则大文件被截断。
- **`read` 不判断返回值** → 读到 EOF(0) 还在用 buf，读到垃圾。
- **忘了处理 `EINTR`** → 程序偶发失败，难复现。
- **`fork` 后子进程没 `_exit`** → 子进程跑完父进程的代码，逻辑全乱（`_exit` 而非 `exit`，避免刷新两次缓冲区）。
