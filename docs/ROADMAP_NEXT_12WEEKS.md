## 2. M0 · 补洞（约 2 天，最优先）

### M0.1 把 `usleep(37000)` 换成真实 `rknn_run`

改造三处，都在 worker 那一侧：

**① worker 函数开头 —— 照搬 `bench_multicore.cpp` 第 46~75 行**

关键就三句：
- `std::vector<char> blob = g_blob;` ← **注意这里是复制，不是引用**
- `rknn_init(&ctx, blob.data(), blob.size(), 0, nullptr);`
- `rknn_set_core_mask(ctx, RKNN_NPU_CORE_0/1/2);` ← 按 worker 编号分配

> **坑（面试也能讲）**：为什么每个线程必须自己复制一份模型内存？
> 因为 `rknn_init` **不会拷贝**你传进去的那块内存，context 内部直接持有这个指针，
> 直到 `rknn_destroy` 为止。三个线程共用一个 blob，会出现重复初始化同一块内存、
> 甚至被运行时改写的问题。所以 bench 里写的是 `= g_blob`（拷贝构造），
> 而不是 `&g_blob`（引用）。
>
> 代价：3 份 6.2MB ≈ 18.6MB 常驻内存，8GB 板上可以忽略。

**② 循环体 —— 把 `usleep(37000)` 换成 `once()` 里的 4 行**

```
rknn_inputs_set(ctx, 1, &in);
rknn_run(ctx, nullptr);
rknn_outputs_get(...);   // want_float = 0，只要原始输出
rknn_outputs_release(...);
```

**③ 线程退出前 —— `rknn_destroy(ctx)`**

> 这一步现在很容易忘，但到了 M1 加 SIGTERM 优雅退出时，它会变成「必须做对」的硬要求。

**验收标准（一眼看出真假）**

```bash
# 终端 A：跑网关
# 终端 B：盯着 NPU 三核
watch -n 0.5 cat /sys/kernel/debug/rknpu/load
```

- **改造前**：`Core0: 0%, Core1: 0%, Core2: 0%`（usleep 骗人的直接证据）
- **改造后**：三个核都在动，各约 49%

这一屏对比，就是将来演示视频第一个镜头。

### M0.2 有界队列 + 丢帧降级

现状：队列无界；摄像头 30fps、NPU 26.9fps，生产快于消费 → 队列只涨不跌，
延迟越积越大，最后客户端收到的是几十秒前的画面。

要做三件事：

1. **给队列设上限**（先试 2 帧，正好覆盖一帧推理的时间）
2. **满了怎么办**——两种策略，想清楚再选：
   - 丢最旧（保实时性：客户端永远看最新画面）← **监控场景选这个**
   - 丢当前（保完整性：不丢中间帧）
3. **计数并上报**：丢了多少帧、丢帧率多少，一起推给客户端

> **面试考点**：这题在「嵌入式 Linux 应用岗」里权重比在端侧岗还高。
> 关键词是**背压（backpressure）**和**削峰**——消费者比生产者慢时，系统该怎么活下来，
> 而不是慢慢憋死。你能拿真项目答，比背概念强十倍。

**验收**：连续跑 5 分钟，队列长度稳定在上限附近、丢帧率稳定、端到端延迟不随时间增长。

## 3. M1 · 第 4 周知识点落地化（约 2 周）

**这一节的写法改了：不再是「做练习题」，而是「给网关加一个功能」。**

| 原计划 | 变成网关的什么功能 | 验收标准 |
|---|---|---|
| **D22** `daemon()` / `setsid` | 网关脱离终端，后台跑 | 关掉 SSH 窗口，网关还在跑、还能收数据 |
| **D23** 信号 `sigaction` | `SIGTERM` → 停 3 个 worker、关 socket、`rknn_destroy`、flush 队列 | `kill -TERM <pid>` 后：无僵尸进程、NPU 负载归零、端口已释放（`ss -lntp` 查得到空） |
| **D24** `epoll` | 从「1 个客户端阻塞」改成「多客户端 + 定时器」 | 两个 `nc` 同时连，互不阻塞；同时能按固定周期上报温度 |
| **D25** `systemd` | 写 `edge-gateway.service`，`Restart=on-failure` | `systemctl status` 显示 running；`kill -9` 后 3 秒内自动拉起；重启板子自动启动 |

**这一节做完，「嵌入式 Linux 应用」那版简历就齐了**——因为它凑齐了工业级服务该有的四件套：
后台驻留、优雅退出、多路复用、进程守护。

> 排错提醒：SIGTERM 优雅退出是最容易写错的一个。
> 常见错法是信号处理函数里直接 `exit()`，或者处理函数里调 `printf`（不是异步信号安全的）。
> 正确做法：信号处理函数里只置一个 `volatile sig_atomic_t g_stop = 1`，
> 让主循环看到标志位后，自己按顺序收拾现场。

## 4. M2 · 砍 DFL 头（约 2~3 周）

三步，按顺序，每步都要能单独验证：

1. **改 ONNX 导出（Python）**：让 `model.22` 直接输出 3 路 raw 特征图
   （stride 8/16/32，各 64 通道），不做 DFL 的 Transpose/Softmax/Reshape。
2. **重转 rknn**：用 rknn-toolkit2 重新量化转换。
   ⚠️ 这一步是整个链路的**最大风险点**——环境、量化校准、算子支持都可能卡住。
3. **C++ 写 decode**：8400×84 的向量化解码 + NMS，放回网关的输出侧。

**为什么这一步值得做**：它是「端侧部署岗」简历上唯一的硬通货，
也是唯一能证明「我不只是会跑 demo，我懂模型结构」的东西。

**为什么放在 M1 之后**：链路长、易卡壳。先把 M0/M1 做完，
手上就有一套「能讲、能演示、面试问不倒」的东西保底，再去碰这个。
